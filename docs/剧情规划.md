# 剧情结构规划（改编总纲）· v0.4 修订

> 本文档是**结构规划**，不是剧本。台词创作的唯一权威来源是仓库根目录的
> `sources/ENDER LILIES 文本集.md`（玩家原话与亡语，原样引用、不得改写）；
> 设定细节以 wiki（`entities/` `events/` `concepts/`）为准。
> 白教区样章（story-src/01~05）是格式与节奏的样板——动笔前先通读它。
>
> **v0.4 修订**（依据 2026-10-30 可行性评估，已与作者确认）：确定改编边界与事件依赖表；
> C 结局采用「保留收集方案」；终章 13 已是可编译可玩的路由原型（占位正文）；

## 一、改编定位

**忠实重述**：《ENDER LILIES》主线做成剧情向视觉小说。叙事骨架沿用原作——

- 主角莉莉（哑巴，台词只存在于回忆中），引导者费林（黑之骑士，全篇的叙述与对话担当）
- 每章 = 一个区域：抵达 → 探索 → 遭遇秽鬼群像（哀鸣引文）→ Boss（守护者/骑士的残响）→ 净化 → **记忆回放** → **亡语**（高潮，原文引用）→ 拾取石板 → 启程（下一章钩子）
- 三结局：A 净化 / B 深渊 / C 尾声

**立项原则：群像角色不做立绘。** 有名有姓的记忆角色才需要立绘（约 10 人）；村民、
商人等群像全部用旁白引文呈现（配 `<area>_quiet` 氛围曲）。美术门槛压到最低。

### 改编边界（审查用两把尺子，分开过）

1. **原文保真**：文本集的记忆/亡语/引文必须原样搬运，审查时逐字核对来源。
2. **演出与结构**：页数、节奏、场景衔接可以改编，但**事件时点**以第二节依赖表为准——
   行程顺序可调整；"何时揭示信息、何时取得物品、何时解读与修复"不得与表冲突。
3. 知识库原文一律不动；与游戏行程不一致处，修订的是游戏源稿的改编方案（在本文档
   记录），不是知识库。

## 四、结局路由（选项级条件已实现）

flag（全部已登记进 `00_设定.md` 的 initial_flags，新 flag 先登记再用）：

- `cleared_<area>`：每章净化完成后置 true（village/forest/catacomb/dungeon/forbidden/fort/castle）
- `relic_1..8`：八枚石板，来源见下表
- `chose_abyss`：终章选择 B 路线时置 true

**石板来源一览（物品 — 来源 — 取得条件 — 补齐途径）**

| 石板 | 章 | 取得条件 | 玩家错过时 |
|---|---|---|---|
| relic_1 | 05 启程 | 主线必得（解读石板文书、护身符苏醒） | 不可缺失 |
| relic_2~7 | 06~11 | 主线必得（各章净化后的遗物页） | 终章「追忆」页补齐 |
| relic_8 | 12 都城 | **可选探索取得**（探索/选择分支） | 终章「追忆」页补齐 |

设计意图：八枚一周目内必可集齐；C 选项在集齐前不可见，因此**首次游玩自然落在
A，C 是留给用心探索者的额外奖励**（参考原作「尾声」定位）。

**终章 c13 结构（已实现为可编译可玩的原型，正文待终稿）**：

```
抵达边境之泉（bg spring，music awakening）
→ 「追忆」页：relic_1~8 各一个条件选项（@when relic_n=false，选中补齐后回到本页；
  已持有的不显示）→「走向泉水深处」
→ 芙莉蒂雅的幻影 → 选项：
   A「净化她」                       → 结局 A（文本集 223-240）
   B「放弃净化，走向深渊最深处」      -> 选项下 @set chose_abyss=true
     → bg abyss，@music boss_final_intro boss_final_outro → 结局 B（对话 869-924）
   C「唤醒古代咒术，修复守护宝具」
     选项下 @when relic_1=true,…,relic_8=true（八枚齐全才显示）→ 结局 C（241-282）
→ 三个结局各自经「（完）」页跳 #coda 收束，不得顺序落入其他结局
```

语法要点：**条件选项 = 选项行下缩进 `@when`**（编译器与运行时已支持并纳入冒烟）；
写成页面级 `@when` 会隐藏整页，不是想要的效果。

## 六、给 Gemini 的章节资料包（替代单一提示词）

每章动笔前，由合入侧准备一份**封闭资料包**，缺一不算开工：

1. 本章开场的角色认知 / 地点 / 物品 / flag 状态（对照第二节依赖表）；
2. 本章结束必须达成的状态与下一章接口（`@set` 清单、启程钩子）；
3. 必引原文与可选原文清单（含稳定来源编号；行号以当时核对为准）；
4. 本章允许使用的角色 / 表情 / 背景 / 音乐 / flag 白名单；
5. 已批准的场景提纲 + `docs/源稿格式.md` + 一份可编译示例（可直接指向
   `story-src/13_终章.md` 路由原型与 01~05 样章）。

先定提纲，再让模型补连接段落；原文引用尽量按来源编号由合入侧核对插入。
Gemini 若没有仓库与终端权限，**编译与冒烟一律由合入侧执行**，提示词里的
"运行命令"不视为已完成测试。

资料包就位后可整段粘贴的提示词：

```text
任务：为 ENDER LILIES 同人视觉小说撰写「<章节名>」一章的场景源稿。
先读：docs/源稿格式.md（语法严格照做，空行分页，一块=一页）、
story-src/01_苏醒.md 至 05_启程.md（白教区样章，模仿节奏与密度）、
story-src/13_终章.md（条件选项与多路由的写法示例）、
随资料包给出的本章必引原文清单与场景提纲。

硬性规则：
- 台词原文（记忆/亡语/引文）从文本集原样搬运，禁止改写润色；你的工作是
  在原文之间补足场景描写、费林的引导对话与转场。
- 莉莉全程无台词；她的"我"心声每章不超过 2 页，每页一句。
- 费林承担全部对话；亡语页必须以「（亡语）」结尾标记。
- 页数按提纲的情绪转折分配（白教区 72 页是样章特例；后续区域章参考 18~26 页），
  每页 20~60 字是新写连接页的目标；必引长原文允许分页，不为凑字数改写原文。
- Boss 段一条指令两个参数：@music boss_<area>_intro boss_<area>_outro
  （不存在独立的 @music_outro 指令）；净化后 @music <area>_quiet。
- 选项下缩进的 @set / @when 只允许使用资料包 flag 白名单里的键；如需新 flag，
  先在交付说明中提出，登记进 story-src/00_设定.md 的 initial_flags 后才能引用。
  除 relic_8（12 章可选探索）外，石板均主线必得；每章结构：
  @music 区域曲 → Boss 段 → @music <area>_quiet 记忆回放 → 亡语 →
  @set cleared_<area>=true → 遗物页 @set relic_<n>=true → 启程页。
- 只交付源稿内容与自检说明；python tools/build_story.py 与
  godot --headless --path . -- --smoke 由合入侧执行并回传结果。
```
